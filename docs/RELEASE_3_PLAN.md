# План третьего релиза (R3) — аналитика, AI, расширения и запуск

Срок: месяц 6 (недели 23–26). Предусловие: R1 и R2 в работе. Схема: модели с тегом [R3] в `db/schema.prisma` (PerformanceThreshold, AiGeneration и др.).

## 1. Цель R3

Дать администрации и завучам аналитику, добавить AI-помощников в безопасном виде, довести всё до стабильного запуска для всей школы: производительность, безопасность, документация и обучение.

## 2. Что входит

- **Insights (админ и завучи):** успеваемость по параллелям, классам, предметам, учителям; динамика между периодами; посещаемость; нагрузка заданий; распределение оценок 1–7 и 2–5; исключения по порогам.
- **DP-аналитика:** сумма IBDP, средний IB-балл, число учеников ниже 24, сравнение со среднемировым IBDP; пороги (сумма < 24, оценка < 4, балл < 40%) из PerformanceThreshold.
- **Planning insights:** покрытие критериев, подходов к обучению (ATL), концепций и контекстов по юнитам; пустые и не опубликованные юниты.
- **Менеджер заданий:** сводка по всем заданиям школы, просрочки проверки, нагрузка учеников (правило не более 3 суммативных в день).
- **Сигналы раннего риска:** ученики с падением оценок, пропусками, пропущенными работами; уведомление классному руководителю и завучу.
- **AI (с самой первой версии заложен интерфейс):** помощник учителя (черновик описания юнита, формулировки заданий, обратная связь по критерию, комментарии для отчётов), помощь переводу каталогов, поиск по планам. Данные учеников в модель отправляются обезличенно и только по явному действию учителя; результаты в AiGeneration с автором, типом и принятием/отклонением.
- **Доступность и полировка:** мобильный вид родителя и ученика, быстрые действия, поиск, массовые операции.
- **Безопасность и эксплуатация:** аудит прав доступа, резервное копирование и проверка восстановления, мониторинг, лимиты, политика хранения данных, логи доступа.
- **Запуск школы:** обучение учителей и родителей, видео-инструкции, документация администратора, поддержка в первый триместр.

## 3. Этапы по неделям

**Неделя 23. Insights.** Витрины данных, фильтры по программе, параллели, периоду; пороговые правила; доступ только для админа и завучей.

**Неделя 24. Planning insights, менеджер заданий, сигналы риска.**

**Неделя 25. AI.** Провайдер и политика приватности, обезличивание, интерфейсы для учителя, журнал генераций, лимиты.

**Неделя 26. Закрытие.** Нагрузочное и пентест-проверка, бэкап-восстановление, обучение, документация, переход всей школы, план поддержки.

## 4. Эпики

1. Аналитика и пороги.
2. Planning insights и менеджер заданий.
3. Ранние сигналы и уведомления.
4. AI-функции и приватность.
5. Безопасность, наблюдаемость, бэкапы.
6. Производительность и мобильные виды.
7. Обучение, документация, поддержка.

## 5. Критерии приёмки

- Завуч видит сводку по параллели за период за ≤ 3 секунды на реальном объёме данных школы; учитель и родитель аналитику не видят.
- Пороги меняются администратором без разработчика.
- AI не получает ФИО и идентификаторы учеников; каждый запрос и результат записан; учитель всегда подтверждает текст перед использованием.
- Восстановление из бэкапа проверено на практике; есть план реагирования на инциденты.
- Все учителя MYP и DP прошли обучение; поддержка в первый триместр организована.

## 6. Риски

1. **Месяц на всё** — если R1/R2 сдвинутся, R3 урезается: оставить Insights по успеваемости и посещаемости и базовый AI, остальное перенести на следующий цикл.
2. **Приватность AI и законодательство РК:** выбор провайдера и размещения нужно решить заранее; при невозможности — только локальная модель или отложить.
3. **Качество данных:** аналитика отражает ошибки ввода; нужны проверки и справочники.
4. **Нагрузка поддержки** после запуска: заложить дежурство команды.

## 7. После запуска (бэклог)

Полная диплом-калькуляция DP (45 баллов), интеграции с другими системами, публичное API, мобильное приложение, расширенные формы отчётности, кросс-школьный режим (модель School уже готова).
